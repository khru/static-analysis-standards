# Static Rule Guidance

This document is the operational guide for every rule registered in
`src/rules/registry.ts`. The descriptions below are intentionally specific to
the implemented AST trigger, not generic design advice. For every finding they
answer four questions:

- **Problem**: what syntax the rule actually reports.
- **Origin**: how that syntax usually entered the code.
- **Why**: the concrete maintenance, correctness or test risk.
- **Solutions**: one or more ways to remove the risk, or a justified exception.

The implementation remains authoritative. This document explains a finding; it
does not turn a review candidate into a blocking error. Scope qualifiers such as
“domain/application” and “outside tests” are part of each rule's contract.

## Quality Rules

| Rule                                 | Problem                                                                                                                                                                              | Origin                                                                                     | Why                                                                                  | Solutions                                                                                                            |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `max-function-statements`            | Reports block-bodied functions with more than 50 configured statements in their own body; nested functions/blocks are not counted as the outer function's statements.                | One operation accumulated policy and orchestration.                                        | Large operations are difficult to understand, test and change safely.                | Extract cohesive operations; keep orchestration at the application boundary; justify a mechanical adapter exception. |
| `max-nesting-depth`                  | Reports `if`, loop, `switch`, `try` and `catch` nodes beyond nesting depth 3 within a function.                                                                                      | Guards and branches were composed inline.                                                  | Preconditions become hidden and the path space grows.                                | Use guard clauses; extract a named policy or collaborator.                                                           |
| `no-abbreviated-names`               | Outside tests, reports catalogued shortened segments in declarations, parameters, classes, types, methods and fields.                                                                | Convenience shortened shared vocabulary.                                                   | Readers must infer intent and searchability is reduced.                              | Spell out the domain/technical term; retain only approved standard acronyms.                                         |
| `no-boolean-parameter`               | Reports function-like parameters whose direct annotation is `boolean`, including defaults and parameter properties.                                                                  | Two behaviors were compressed into one API.                                                | Call sites are boolean-blind and the function has multiple reasons to change.        | Split commands; use a named discriminant/options object when variation is real.                                      |
| `no-date-construction-outside-clock` | Outside tests, clock files, domain files and application files, reports `new Date()` and `Date.now()`.                                                                               | Platform time was read in infrastructure or composition without an explicit time boundary. | Time becomes implicit and tests or operational code can become non-deterministic.    | Inject `Clock`; create UTC instants at the boundary; document a deliberate host-infrastructure exception.            |
| `no-deprecated-api-usage`            | Outside tests, reports calls to catalogued deprecated globals or non-computed member methods. Property reads alone are not reported.                                                 | A migration was started but not completed.                                                 | Legacy behavior remains alive and future removal becomes unsafe.                     | Migrate to the replacement; remove aliases and compatibility scaffolding after the contract migration.               |
| `no-direct-process-env-access`       | Outside tests and configuration files, reports `process.env.KEY` and deeper member reads; bare `process.env` passed as a value is allowed.                                           | Configuration leaked from infrastructure into runtime code.                                | Values are unvalidated, difficult to substitute and hard to test deterministically.  | Read variables in one typed configuration loader and inject the resulting port/value.                                |
| `no-empty-catch`                     | Reports every `catch` clause whose body contains no statements.                                                                                                                      | Failure handling was omitted or an empty recovery was used as a shortcut.                  | Operational failures disappear and callers cannot choose a policy.                   | Recover explicitly; translate/rethrow a typed error; document a best-effort boundary with an observable outcome.     |
| `no-generic-error`                   | Outside tests, reports `Error(...)` and `new Error(...)` when the callee is the unqualified `Error` identifier.                                                                      | A failure was created without an owning vocabulary.                                        | Callers cannot distinguish intent and transport mapping falls back to magic strings. | Define a typed local error and closed message/code catalog.                                                          |
| `no-generic-names-in-domain`         | In non-test domain/application code, reports catalogued generic noun segments in symbols and generic noun/verb method names.                                                         | Implementation placeholders replaced business language.                                    | The model cannot be understood without inspecting implementation.                    | Name the business role, state, invariant or operation explicitly.                                                    |
| `no-interface-prefix-suffix`         | Outside tests, reports interfaces ending in `Interface` or starting with `I` followed by a capital letter.                                                                           | Naming followed language-construct conventions instead of capability.                      | Names expose syntax rather than the port's responsibility.                           | Name the capability/port directly.                                                                                   |
| `no-local-time-construction`         | Outside tests, reports `new Date` with two or more arguments; it does not detect local getters or every possible local-time API.                                                     | Calendar components were interpreted through the local timezone.                           | The resulting instant can vary with timezone and DST.                                | Use `Date.UTC`, an injected clock, or a validated UTC instant; narrow/justify an intentional platform exception.     |
| `no-magic-numbers`                   | In non-test domain/application code, reports numeric literals not covered by the configured protocol, type-position, class-field and literal-constant exceptions.                    | A threshold or protocol value was left inline.                                             | Meaning and change impact are invisible.                                             | Name the constant/value object; preserve standard protocol values only through the documented allowlist.             |
| `no-magic-strings`                   | In non-test domain/application code, reports non-empty strings outside the configured data, definition, import, class-field, constant, symbol-description and error-name exceptions. | A state/event/protocol vocabulary was duplicated inline.                                   | Typos and inconsistent cross-boundary states become silent behavior changes.         | Use a local closed catalog, enum or discriminant constant.                                                           |
| `no-mixed-abstraction-levels`        | In non-test domain/application functions, reports inline computation combined with collaborator-result naming or a call/new command; constructors are excluded.                      | Mechanism was added beside orchestration.                                                  | Policy boundaries become unclear and changes have a broad blast radius.              | Extract mechanism behind a port/adapter; keep one abstraction level per method.                                      |
| `no-mixed-effect-categories`         | In non-test domain/application functions, reports a value-returning path together with member assignment or a catalogued mutating call.                                              | Query and command behavior were combined.                                                  | Ordering, retries and tests become difficult to reason about.                        | Separate query and command; isolate mutation behind an explicit collaborator.                                        |
| `no-nested-ternary`                  | Reports a conditional expression whose consequent or alternate is itself a conditional expression.                                                                                   | Compact syntax replaced named decision logic.                                              | Evaluation order and edge cases are hard to scan.                                    | Use guard clauses or a named decision function.                                                                      |
| `no-static-service-locator`          | Reports mutable/uninitialized static fields and catalogued locator methods that return a new instance of their own class in the method scope.                                        | Ambient composition replaced explicit dependency wiring.                                   | Dependencies are hidden and state leaks between tests.                               | Compose at the root; inject typed ports/factories; make state instance-owned.                                        |
| `no-stringly-typed-dispatch`         | Outside tests, reports switches with at least two non-empty string cases and top-level `if/else if` chains with at least two string equality comparisons on the same operand.        | Closed variants were represented as arbitrary text.                                        | Renames and unsupported values are not compiler-visible.                             | Use a discriminated union and a typed data-driven map.                                                               |
| `no-uncommunicative-names`           | Outside tests, reports catalogued vague names and non-allowlisted one-character names on variables, functions, classes, types, methods, fields and import aliases.                   | Placeholder names survived implementation growth.                                          | Every use requires source inspection.                                                | Name the role, effect, unit or business concept explicitly.                                                          |
| `prefer-data-driven-dispatch`        | Outside tests, reports switches with at least two cases when every case has exactly one return statement.                                                                            | A lookup table was encoded as branches.                                                    | New cases require control-flow edits and omissions are easy to miss.                 | Use a typed map/catalog; handle missing keys explicitly.                                                             |
| `prefer-intl-date-formatting`        | Outside tests, reports `toLocaleDateString`, `toLocaleTimeString` and `toLocaleString` member calls on any receiver.                                                                 | Locale/timezone behavior was delegated to the runtime.                                     | Output differs between machines and environments.                                    | Use `Intl.DateTimeFormat` with explicit locale and timezone.                                                         |
| `prefer-utc-date-getters`            | Outside tests, reports calls to catalogued local date getter names, regardless of receiver type.                                                                                     | A UTC instant was interpreted with local calendar methods.                                 | Results vary by machine timezone.                                                    | Use UTC getters or a domain time abstraction.                                                                        |
| `prefer-utc-date-setters`            | Outside tests, reports calls to catalogued local date setter names, regardless of receiver type.                                                                                     | Calendar mutation used local timezone semantics.                                           | DST and timezone alter the resulting instant.                                        | Use UTC setters or reconstruct a validated UTC instant.                                                              |
| `prefer-utc-serialization`           | Outside tests, reports `toDateString` and `toTimeString` member calls, regardless of receiver type.                                                                                  | Local serialization was selected implicitly.                                               | Consumers receive ambiguous or shifted timestamps.                                   | Serialize UTC with `toISOString` or an explicit UTC serializer.                                                      |

## Review Candidates

| Rule                                   | Problem                                                                                                                                                                  | Origin                                                                   | Why                                                               | Solutions                                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `disconnected-method-clusters`         | Reports a domain/application class with at least two state-touching methods, at least two touched properties, and pairwise-disjoint property sets.                       | Multiple responsibilities accumulated in one class.                      | Cohesion falls and unrelated changes collide.                     | Split by reason to change after checking shared invariants.                                    |
| `fat-interface-candidate`              | Reports a domain/application interface with more than 10 body members.                                                                                                   | A port widened to avoid another seam.                                    | Implementations and consumers carry unrelated obligations.        | Split ports by client need and capability.                                                     |
| `feature-envy-candidate`               | Reports a domain/application method with at least two distinct direct `parameter.property` reads and no direct `this.property` reads.                                    | Policy was placed near a caller rather than its information.             | Ownership is unclear and behavior scatters.                       | Move behavior to the information expert or introduce a focused domain service.                 |
| `few-instance-variables`               | Reports a domain/application class with more than five non-static property definitions; despite its legacy name, it detects many fields, not few.                        | State spread across a large class.                                       | State ownership and cohesion become difficult to maintain.        | Group state into value objects; split the class by responsibility.                             |
| `first-class-collection-candidate`     | Reports a domain/application class with exactly one property whose annotation is an array/tuple or catalogued collection reference.                                      | Raw collection behavior lacks an owner.                                  | Invariants and operations are duplicated at call sites.           | Introduce a collection value object when it owns rules; otherwise justify the simple holder.   |
| `max-one-indentation`                  | Outside tests, reports functions whose deepest nested block depth reaches at least two relative to the function body.                                                    | Several blocks were placed inside one operation.                         | The primary action is visually hidden.                            | Guard early and extract the nested policy; retain necessary mechanical nesting with rationale. |
| `no-abbreviations`                     | Outside tests, reports identifiers of one to three lowercase alphanumeric characters unless the short-name/abbreviation catalog allows them.                             | Local names were shortened for convenience.                              | Searchability and shared language degrade.                        | Use the complete term or an established protocol acronym.                                      |
| `no-concrete-low-level-dependency`     | Reports domain/application static imports and literal dynamic imports whose path contains a catalogued low-level segment such as `persistence`, `adapter` or `client`.   | The adapter boundary was skipped.                                        | Replacements and isolated tests require production edits.         | Depend on an owning port and translate in composition.                                         |
| `no-else`                              | Outside tests, reports every `else`, including `else if` and cases where early return is not obviously possible.                                                         | Alternatives were written as nested branches.                            | Extra indentation can obscure the normal path.                    | Use guard returns where valid; otherwise retain and document a genuinely paired alternative.   |
| `no-getters-setters`                   | Reports any catalogued accessor method in non-test domain/application code, regardless of visibility or mutability.                                                      | Representation was exposed as property plumbing.                         | Callers can bypass invariants and representation becomes the API. | Expose intention-revealing behavior or immutable values.                                       |
| `one-dot-per-line`                     | Outside tests, reports ordinary call chains with at least two method names, or at least three when rooted in `this`/`super`; catalogued pipeline operators are exempt.   | Callers navigate object graphs directly.                                 | Ownership boundaries and Law of Demeter are obscured.             | Add behavior to the owner or introduce a focused port.                                         |
| `small-class-candidate`                | Reports a domain/application class with at least eight non-constructor methods; despite its name, it detects large behavior, not too little behavior.                    | Responsibilities accumulated in one class.                               | Cohesion and change risk decline.                                 | Split by responsibility; retain a material boundary only when it protects variation.           |
| `wrap-primitives-candidate`            | Reports domain/application class properties and interface members annotated with catalogued primitive keyword types.                                                     | A domain concept remained a raw string/number/boolean.                   | Validation and meaning are duplicated.                            | Introduce a value object with parsing and invariants.                                          |
| `binary-operator-in-name`              | Reports domain/application functions, methods and classes whose name segments contain `and`, `or`, `not`, `in` or `between`; variables and interfaces are not inspected. | Multiple responsibilities were compressed into one name.                 | A missing concept or split is concealed.                          | Split responsibilities or name the single policy explicitly.                                   |
| `callback-hell`                        | Reports arrow/function expressions nested to depth at least three through AST traversal; the heuristic is not limited to callback arguments.                             | Asynchronous or nested work was composed inline.                         | Error and lifecycle paths become hard to follow.                  | Extract named operations or use structured async composition.                                  |
| `combinatorial-explosion`              | Reports non-test domain/application block-bodied functions with at least four `if` statements in their own scope; nested functions and other branch kinds are excluded.  | Independent behavior dimensions accumulated in one function.             | Testing and reasoning grow combinatorially.                       | Use typed policies/tables or separate use cases.                                               |
| `complicated-boolean-expression`       | Reports domain/application conditions with at least three recursively counted binary/logical operands in `if`, loops or ternaries.                                       | Several decisions were compressed into one expression.                   | Precedence and negation hide the business rule.                   | Name predicates and compose them at the policy boundary.                                       |
| `no-high-cognitive-boolean-expression` | Reports boolean expressions whose nested operators and comparisons exceed the cognitive point limit.                                                                     | Comparisons and logical alternatives were compressed into one condition. | Precedence and branching impose excessive cognitive load.         | Extract named predicates and compose them at the policy boundary.                              |
| `complicated-regex-expression`         | Reports domain/application regex literals with source length at least 20 or at least three grouping/alternation characters.                                              | Grammar was embedded as an opaque regex.                                 | Small edits can introduce invisible matching defects.             | Name/split patterns or use a parser.                                                           |
| `conditional-complexity`               | Reports domain/application functions with complexity at least six, counting decisions from conditions, loops, switches, catches and logical operators.                   | Variants accumulated in one operation.                                   | Branch coverage and change risk increase together.                | Split policies or use data-driven dispatch.                                                    |
| `data-clump`                           | Reports repeated groups of at least three simple identifier parameters with the same sorted name set in one domain/application file.                                     | A concept lacks a value or command object.                               | Callers can reorder or partially supply related data.             | Introduce a value object or explicit command.                                                  |
| `global-data`                          | Reports top-level mutable `let`/`var` identifier declarations in domain/application code; `const` is intentionally excluded.                                             | State was made ambient for convenience.                                  | Tests interfere and ownership is undefined.                       | Scope state to composition or inject a stateful port.                                          |
| `imperative-loops`                     | Reports every `for`, `for in`, `for of`, `while` and `do while` in domain/application code; it does not decide whether a loop is mechanically necessary.                 | Collection/control-flow behavior was written procedurally.               | Mutation and early exits can obscure the rule.                    | Use a named collection operation; retain a loop when mechanics require it and document why.    |
| `inappropriate-static`                 | Reports non-static instance methods whose body contains no `ThisExpression`; nested functions are excluded.                                                              | A utility operation was placed on a stateful class.                      | The class boundary may be accidental.                             | Make it a pure function/static utility or give the class real state ownership.                 |
| `long-parameter-list`                  | Reports domain/application functions, arrows and methods with more than four parameters.                                                                                 | A command/value object was not introduced.                               | Call sites are fragile and arguments are easy to confuse.         | Use a named parameter object or split the responsibility.                                      |
| `middle-man`                           | Reports ordinary instance methods whose body is exactly one return of a non-computed member call; forwarding `this` is not required by the heuristic.                    | An abstraction was added without meaningful translation.                 | Indirection grows while responsibility remains unclear.           | Remove it or make its translation/ownership meaningful.                                        |
| `mutable-data`                         | Reports every non-test domain/application `let` declarator with an identifier binding, including never-reassigned locals.                                                | State transitions were implemented procedurally.                         | Intermediate states and ordering are harder to reason about.      | Prefer `const`, immutable values and explicit transitions; justify unavoidable mechanics.      |
| `null-check`                           | Reports `if`, loop and ternary tests comparing to `null`/`undefined` or involving `typeof`; it does not detect every `??`, optional-chain or negation form.              | Validation was deferred past the boundary.                               | The same uncertainty spreads through policy code.                 | Validate once at the frontier and use a non-null value object/Option.                          |
| `status-variable`                      | Reports a local initialized with a string literal and assigned another string literal later in its enclosing function.                                                   | Multiple states were encoded in one mutable slot.                        | Transitions are implicit and invalid states are easy to create.   | Use a discriminated union or separate state operations.                                        |
| `temporary-field`                      | Reports an instance field referenced by exactly one ordinary method in a class with at least two such methods; only direct `this.field` references count.                | Temporary workflow state was stored on a broad object.                   | Lifetime and ownership are unclear.                               | Keep it local or extract a workflow object.                                                    |
| `what-comment`                         | Reports sufficiently long comments whose significant words all occur in the annotated node's source; it identifies literal restatements, not all unhelpful comments.     | Names or structure failed to communicate.                                | Comments duplicate implementation and drift.                      | Improve names/design; keep comments for why, constraints or external behavior.                 |

## Domain, Architecture and Testing Rules

| Rule                                | Problem                                                                                                                                                                       | Origin                                             | Why                                                                   | Solutions                                                                            |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `no-ambient-clock`                  | Reports `new Date()` and `Date.now()` in non-test domain/application code.                                                                                                    | Time was read directly instead of injected.        | Temporal policy and tests become non-deterministic.                   | Inject `Clock` and pass an instant into the policy.                                  |
| `no-ambient-randomness`             | Reports bare `randomUUID`, `Math.random`, `crypto.randomUUID` and `crypto.getRandomValues` calls in non-test domain/application code.                                         | Random generation leaked into policy.              | Replays and tests cannot be deterministic.                            | Inject an ID/random-source port at composition.                                      |
| `no-framework-types`                | Reports non-test static imports whose source equals or starts with a configured framework package; it checks import source, not actual type usage.                            | Framework vocabulary crossed the domain boundary.  | The domain cannot evolve independently of presentation/transport.     | Translate framework values at the adapter frontier.                                  |
| `no-orm-types`                      | Reports non-test static imports whose source equals or starts with a configured ORM package.                                                                                  | Persistence representation leaked into policy.     | Schema changes become business changes and tests need infrastructure. | Define local ports/types and translate rows in adapters.                             |
| `depend-on-port-not-adapter`        | Reports application non-test static imports whose source contains `infrastructure`, regardless of imported symbol.                                                            | Composition bypassed the owning interface.         | Replacements and fakes require production edits.                      | Import the owning port and wire the adapter at composition.                          |
| `no-concrete-repository-dependency` | Reports named imports whose imported name matches the configured concrete repository prefixes and ends in `Repository`; default/namespace imports are outside this heuristic. | Storage mechanism became the application contract. | Business policy couples to persistence.                               | Depend on a repository port in domain language.                                      |
| `no-test-control-flow`              | In recognized test callbacks, reports `if`, loops, `switch` and ternary nodes in the callback's own scope; nested functions are excluded.                                     | Operational branching entered the example.         | Tests reproduce behavior or hide Arrange/Act/Assert.                  | Move mechanics to fixtures/hooks; use semantic `it.each` only for same-shaped cases. |
| `no-try-finally-in-tests`           | In recognized test callbacks, reports every `try` with a `finally` in the callback's own scope; nested functions are excluded.                                                | Cleanup was used to repair shared state.           | Failures can leave order-dependent state.                             | Use isolated fixtures and guaranteed lifecycle hooks.                                |

## Maintenance Contract

When a rule implementation changes, update this document in the same change.
The `rule-guidance.test.ts` test compares every registered rule with a populated
row here, so a new or renamed rule cannot silently ship without Problem, Origin,
Why and Solutions documentation.
